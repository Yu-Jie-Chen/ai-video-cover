# 视频无损封装为 MP4

当用户要求把现有 `.qt`、`.mov` 等视频转为 MP4 时，运行随附脚本。它复制已有压缩音视频流，不重新编码；容器、文件体积和部分容器元数据可能变化。制作静态封面不需要运行此工具。

## 在 Windows 双击使用

将 `scripts/lossless_to_mp4.py` 和 `scripts/无损转换为MP4.cmd` 放在视频文件夹中，双击 `无损转换为MP4.cmd`。只扫描所在文件夹，不扫描子目录；已有 MP4 跳过，同名 MP4 不覆盖，原片始终保留。

需要 Python 3.9+ 和 FFmpeg。FFmpeg 可放入 PATH、与 Python 脚本放在同一目录，或安装：

```powershell
python -m pip install imageio-ffmpeg
```

脚本也识别 `FFMPEG_BINARY`、`--ffmpeg` 指定的路径，以及 Windows 本机缓存 `%LOCALAPPDATA%\ai-video-cover\ffmpeg\ffmpeg.exe`。脚本本身不联网下载工具，不上传视频。

## 指定文件夹运行

先查看计划：

```powershell
python scripts/lossless_to_mp4.py "G:\上传视频" --dry-run
```

正式转换：

```powershell
python scripts/lossless_to_mp4.py "G:\上传视频"
```

不在 PATH 中的 FFmpeg 可追加 `--ffmpeg "D:\工具\ffmpeg.exe"`。`--report` 可指定一个尚不存在的 JSON 报告路径。

## 无损与校验范围

- 使用 `-map 0 -c copy`，保留所有可被 MP4 容纳的流，并复制可兼容的元数据和章节。
- 对所有视频流和音频流比较转换前后的 SHA-256，再完整解码输出并检查错误。
- 比较原片转换前后的文件 SHA-256，并检查输出 MP4 容器。
- 校验通过才发布同名 `.mp4`；失败清理本次临时文件，不覆盖或删除原片。
- 不兼容 MP4 的编码或轨道、损坏的源文件、流哈希不一致都报失败；不会自动改为有损编码，也不会悄悄丢弃不兼容的轨道。

这种保守核验可能拒绝需要改变码流封装形式的输入；拒绝不表示一定无法通过其他方式无损转换。该工具不会认证字幕、章节及所有元数据逐字节一致，也不承诺所有播放器都支持源片编码。

运行结束会生成 `无损转MP4-校验报告-时间-随机标识.json`。报告区分已转换并校验、同名文件跳过、失败；**跳过不代表已校验**。退出码 `0` 表示无失败（可能全部跳过），`1` 表示存在转换或依赖错误，`2` 表示参数错误，`130` 表示用户中断。

文件较大时，完整解码校验比封装本身耗时更久。请勿在转换期间编辑源视频。对外报告完成时，以校验报告为准。
